# 대형 게임 트랙 (1.0 이후)

목표: 1.0(인디·스타일라이즈드·모바일·웹) 다음 단계로, **오픈월드와 타르코프급 멀티플레이어 FPS**처럼 크고 정교한 게임까지 만들 수 있게 합니다.

원칙
- 1.0을 먼저 끝냅니다. 이 트랙은 1.0 이후에 시작합니다.
- 1.0 설계(RHI 추상화, 명령 버스, 씬 레이어 분할, 리플렉션, 바이너리 쿠킹)는 이 트랙을 막지 않도록 이미 맞춰 두었습니다. 기초를 다시 짜지 않습니다.
- 순서는 **의존 관계** 기준입니다. 렌더러와 월드 스트리밍이 다른 모든 기능의 바닥입니다.

---

## 단계

| 단계 | 내용 | 완료 기준 |
|---|---|---|
| **L1** 렌더러 기반 | SDL_GPU 백엔드(Vulkan·D3D12·Metal), 멀티스레드 명령 기록, GPU 기반 컬링과 드로우, 오클루전 컬링 | 같은 장면을 OpenGL 대비 Draw call 병목 없이 렌더링, macOS에서 실행 |
| **L2** 큰 월드 | 월드 스트리밍, 원점 이동(64비트 위치), 자동 LOD·HLOD, 터레인, 대량 식생, 비동기 에셋 스트리밍 | 8×8km 테스트 맵을 로딩 화면 없이 이동 |
| **L3** 고급 그래픽 | 실시간 GI → [Halo GI](../features/global-illumination.md) (Tier 1~2), 고급 그림자(가상 섀도맵 검토), 볼류메트릭 안개·구름, 시간대 변화 | 낮밤이 바뀌는 오픈월드 장면을 목표 사양 PC에서 60fps |
| **L4** 멀티플레이어 | 서버 권한 구조, 리플리케이션, 클라이언트 예측·지연 보정, 전용 서버 빌드(헤드리스), 매치메이킹 연동 | 32명 동시 접속 테스트 매치 |
| **L5** 정밀 전투 | 탄도·관통·재질별 피해, 부위 판정·방어구, 1인칭 무기 리그, 반동·흔들림, 모듈식 부착물 | 타르코프식 사격 손맛 프로토타입 |
| **L6** 애니메이션 고도화 | 모션 매칭, 전신 IK, 1인칭·3인칭 동기화, 리타게팅 | 무기·자세 변화가 자연스러운 캐릭터 |
| **L7** 게임 시스템·운영 | 데이터 중심 아이템·인벤토리, 서버 영속화(저장), 안티치트 연동, 크래시 리포터, 패치 파이프라인 | 계정·인벤토리가 유지되는 라이브 서비스 테스트 |

L1·L2가 끝나면 싱글 오픈월드가 가능하고, L4·L5까지 가면 대형 멀티플레이어 FPS가 가능해집니다.

---

## 영역별 상세

### 큰 월드 (L2)
- **월드 스트리밍:** 씬 레이어 분할을 확장해 월드를 격자 셀로 나눕니다. 셀은 각자 `.jsonl` 파일이라, 사람이나 에이전트가 셀 단위로 동시에 편집할 수 있습니다 (텍스트 저장의 장점이 커지는 부분).
- **좌표:** 오브젝트 위치는 64비트로 저장하고, 렌더링·물리는 카메라 근처 원점을 기준으로 계산해 먼 거리에서도 떨리지 않게 합니다.
- **LOD/HLOD:** 임포트할 때 자동 LOD 생성, 멀리 있는 셀은 합친 저해상도 메시(HLOD)로 대체.
- **터레인·식생:** 하이트맵 터레인, GPU 인스턴싱 식생, 거리별 밀도 조절.
- **AI 친화:** `bdg world cells --near x,z`처럼 셀 단위로 읽고 쓰는 명령. 거대한 맵도 필요한 셀만 컨텍스트에 넣습니다.

### 렌더링 (L1·L3)
- OpenGL은 멀티스레드 명령 기록과 최신 GPU 기능에 한계가 있어, 대형 게임은 SDL_GPU 백엔드를 기본으로 합니다. OpenGL 백엔드는 저사양·호환용으로 남깁니다.
- 1.0의 스케일러빌리티 그룹에 L3 기능을 단계별로 추가합니다 (Epic 단계에서만 켜지는 식).

### 멀티플레이어 (L4)
- **구조:** 서버가 판정하고 클라이언트는 예측해서 먼저 보여 준 뒤 서버 결과로 보정합니다.
- **리플리케이션:** 리플렉션의 필드 표시에 `[Replicated]`(C#), `BPROPERTY(Replicated)`(C++), 그래프 변수의 "복제" 체크를 추가합니다. 언어 상관없이 같은 규칙.
- **RPC:** `[Server]`, `[Client]`, `[Multicast]` 함수 표시. 그래프 이벤트에도 같은 옵션.
- **전용 서버:** 렌더링·오디오 모듈을 뺀 헤드리스 서버 빌드 (모듈 구조 덕분에 가능).
- **테스트:** 에디터에서 서버 1 + 클라이언트 여러 개를 한 번에 실행, 지연·패킷 손실 시뮬레이션. 플레이 녹화 테스트를 멀티플레이어로 확장.
- **안티치트:** 상용 안티치트(EAC, BattlEye 등) 연동 지점을 마련합니다. 계약과 연동은 게임 개발사의 몫입니다.

### 정밀 전투 (L5)
- 탄도: 총알마다 속도·낙차·공기저항을 계산하고, 물리 엔진의 레이캐스트를 단계별로 이어서 처리.
- 관통: 재질(콘크리트, 나무, 금속…)별 관통력과 감쇠를 데이터 표(`data/materials.tsv`)로 관리. AI와 기획자가 표로 쉽게 조정.
- 부위 판정·방어구: 히트박스별 배율과 방어구 등급을 데이터로.
- 무기: 1인칭 전용 카메라 리그, 반동 커브(타임라인 도구 재사용), 모듈식 부착물(프리팹 소켓).

### 운영 (L7)
- 아이템·인벤토리는 데이터 중심 프레임워크로 제공 (아이템 정의는 TSV/JSON, 로직은 그래프나 C#).
- 서버 저장은 엔진이 특정 DB를 강제하지 않고 저장 인터페이스만 제공합니다.
- 크래시 리포터, 버전별 패치(바뀐 쿠킹 파일만 배포).

---

## 범위 밖 (엔진이 직접 하지 않음)

- 결제, 계정 서비스, 서버 호스팅 운영: 외부 서비스와 연동만 지원
- 안티치트 자체 개발: 상용 솔루션 연동
- 플랫폼별 인증(콘솔 TRC 등): 콘솔 포트 단계에서 별도로

## 현실적인 기대치

- 이 트랙은 1.0보다 큰 작업입니다. 특히 L1(렌더러)과 L4(멀티플레이어)는 각각 전문 인력이 필요한 영역입니다.
- 오픈소스로 공개한다면 이 트랙은 기여자와 함께 진행하는 것을 전제로 계획합니다.
- 그래픽 최상급(언리얼 나나이트·루멘 수준)은 L3 이후에도 목표가 아닙니다. 목표는 "대형 게임을 충분히 좋은 품질로, AI와 함께 빠르게 만드는 것"입니다.

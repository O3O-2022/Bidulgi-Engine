## 🔴 설계를 고쳐야 하는 문제

### 1. 범위가 1인·2인 개발로는 너무 넓음
- **문제:** 언어 5개, 그래픽 백엔드 6개, 플랫폼 7개, 블렌더식 도구, UMG식 UI, 콘솔까지. 상용 엔진 팀이 수년 걸리는 범위입니다.
- **제안:** "설계는 넓게, 구현은 좁게". 인터페이스(RHI, C API, 플랫폼 레이어)는 처음부터 넓게 잡고, 1.0 구현은 아래로 제한합니다.
  - 언어: **C# + Lua** (Python은 에디터 자동화용으로만, Rust·C++ 플러그인은 1.0 이후)
  - 그래픽: **OpenGL 4.5 + GLES 3.0/WebGL2**
  - 플랫폼: **Windows, Android, Web**
- **영향 문서:** roadmap, scripting, rendering-and-platforms

### 2. 씬 파일의 쉼표 때문에 git 충돌이 잦음
- **문제:** 지금 형식은 `"objects":[ ... ]` 배열이라 줄 끝에 쉼표가 있습니다. 두 사람(또는 에이전트 둘)이 각각 오브젝트를 끝에 추가하면 같은 줄(마지막 오브젝트의 쉼표, `]}`)을 고치게 되어 충돌합니다.
- **제안:** 씬을 **JSONL**로. 첫 줄은 헤더, 그다음 줄부터 오브젝트 하나씩. 쉼표와 닫는 괄호가 없어서 추가·삭제가 다른 줄과 엮이지 않습니다.
  ```jsonl
  {"v":1, "scene":"forest_01", "mode":"3d", "settings":{"gravity":[0,-9.81,0]}}
  {"id":"cam", "type":"Camera", "pos":[0,5,-10], "rot":[20,0,0]}
  {"id":"player", "type":"Mesh", "Mesh":{"model":"models/knight.glb"}}
  ```
- 추가로 **git merge 드라이버**(id 기준 병합)를 제공하면 같은 오브젝트를 다르게 고친 경우만 충돌로 남습니다.
- **영향 문서:** data-formats

### 3. 프리팹 인스턴스의 자식 id가 충돌함
- **문제:** goblin 프리팹 안에 `hpbar` 자식이 있으면, 고블린을 두 마리 놓는 순간 씬에 `hpbar`가 둘이 됩니다. "id는 씬 안에서 고유" 규칙이 깨집니다.
- **제안:** 프리팹 내부 id는 **인스턴스 기준 경로**로 부릅니다. `@g1/hpbar`, `@g2/hpbar`. 프리팹 안의 오브젝트를 고치는 오버라이드도 이 경로로 적습니다.
  ```jsonl
  {"id":"g1", "prefab":"prefabs/goblin.prefab", "pos":[6,0,1], "Health":{"hp":12}, "/hpbar":{"pos":[0,2,0]}}
  ```
- **영향 문서:** data-formats, agent-integration

### 4. 엔진 기본값이 바뀌면 모든 씬이 몰래 바뀜
- **문제:** 기본값을 저장하지 않으므로, 엔진 업데이트에서 `Light.intensity` 기본값이 1 → 2로 바뀌면 모든 씬의 조명이 말없이 밝아집니다.
- **제안:**
  - 기본값을 **엔진 버전과 함께 고정**합니다. 파일의 `"v"`가 어떤 기본값 세트를 쓰는지 정합니다.
  - 기본값을 바꿀 때는 반드시 **마이그레이션**을 같이 넣습니다 (옛 버전 파일을 열면 예전 기본값을 명시적으로 써 넣음).
  - CI에서 "기본값 변경 + 마이그레이션 누락"을 검사합니다.
- **영향 문서:** data-formats, command-bus-and-reflection

### 5. AI가 에디터 밖에서 파일을 직접 고치면 충돌
- **문제:** 에디터가 켜진 상태에서 AI가 `.scene` 파일을 직접 고치면, 메모리 상태, Undo 기록, 디스크 내용이 서로 어긋납니다. `.meta` 없이 에셋만 옮기면 GUID 추적도 끊깁니다.
- **제안:**
  - **파일 감시자**: 디스크 변경을 감지해 다시 불러오고, Undo 기록에 "외부 편집" 항목으로 남김
  - 에디터에 저장 안 된 변경이 있을 때 외부 편집이 오면 → 비교 화면에서 선택
  - **`bdg mv`, `bdg rm` 명령**: 에셋을 `.meta`와 함께 옮기고, 참조 경로를 갱신
  - `bdg validate`가 짝 잃은 `.meta`와 깨진 참조를 찾아 고칠 방법을 제시
  - AI 안내 파일에 "에디터가 켜져 있으면 파일 대신 명령을 쓸 것"을 명시
- **영향 문서:** agent-integration, command-bus-and-reflection

### 6. 런타임이 JSON을 그대로 읽으면 느림
- **문제:** 큰 씬을 게임 실행 중에 JSON으로 파싱하면 로딩이 느리고, 모바일에서 특히 불리합니다.
- **제안:** **텍스트는 에디터와 저장소 전용, 빌드는 바이너리.** 쿠킹 단계에서 씬·프리팹·UI·애니메이션을 바이너리로 변환합니다. 에디터의 Play 모드는 메모리에 있는 데이터를 그대로 씁니다.
- **영향 문서:** data-formats, rendering-and-platforms (쿠킹)

### 7. 다국어 스크립트의 객체 수명 문제
- **문제:** C#, Lua 같은 GC 언어가 이미 삭제된 GameObject를 계속 들고 있으면 크래시나 메모리 오염이 생깁니다.
- **제안:** 언어 경계에서는 포인터 대신 **핸들(인덱스 + 세대 번호)**만 넘깁니다. 삭제된 오브젝트에 접근하면 크래시 대신 명확한 에러를 냅니다 (유니티의 "destroyed object" 비교와 같은 효과).
- 핫 리로드 때 스크립트 필드를 직렬화했다가 복원하는 규칙도 언어 공통으로 정합니다.
- **영향 문서:** scripting

### 8. MCP 서버 보안
- **문제:** localhost에 포트를 열면 같은 PC의 아무 프로그램이나 에디터를 조종할 수 있습니다.
- **제안:** 실행할 때마다 **토큰을 발급**하고, 처음 연결할 때 에디터에서 승인하게 합니다. 기본값은 localhost에만 바인딩합니다.
- **영향 문서:** agent-integration, project-settings (Agent)

## 🟡 약점과 대비책

| 항목 | 약점 | 대비책 |
|---|---|---|
| 한 줄 = 오브젝트 하나 | 컴포넌트가 많으면 한 줄이 수백 자가 되어 읽기와 diff가 불편 | 160자를 넘으면 컴포넌트마다 줄을 나누는 포매터 규칙 (JSONL에서는 "한 오브젝트 = 한 블록"으로 완화할지 결정 필요) |
| UI 바인딩 식 | `"@player.Health.hp / max"` 같은 식은 결국 작은 언어를 하나 더 만드는 셈 | 바인딩은 **경로만** 허용(`value`, `max` 따로). 계산이 필요하면 스크립트에서 |
| 애니메이션 대상 이름 | 위젯 이름을 바꾸면 트랙이 끊길 수 있음 | 애니메이션은 반드시 **id**로 참조 (이름 변경과 무관) |
| 월드 공간 UI 입력 | 마우스, 터치, VR 컨트롤러 입력이 따로 놀 수 있음 | 공통 **EventSystem**: 모든 입력을 포인터 이벤트로 바꿔 레이캐스트 |
| 타일맵 문자열 | 팔레트 문자가 많아지면 사람이 읽기 어려움 | 팔레트 최대 개수 권장, 에디터 브러시가 기본 편집 수단 |
| 토큰 추정 | 글자 수 ÷ 4는 한글이 섞이면 크게 틀림 | 실제 토크나이저 기준 수치로 교체(선택), 아니면 "추정" 표기 유지 |
| 결정론 | `bdg sim` 결과가 실행마다 다르면 AI 검증이 흔들림 | 고정 타임스텝 + 시드 고정, Jolt 결정론 모드. 같은 플랫폼 기준으로 보장 |
| C++ 매크로 방식 | 헤더 툴 때문에 빌드가 복잡해짐 | C++은 엔진 확장 용도로 한정, 게임플레이는 C# 권장 |
| 프로젝트 설정 | 같은 Android라도 저사양·고사양 기기가 다름 | 언리얼 **Device Profile**처럼 기기 등급별 덮어쓰기 계층 추가 |
| 스케일러빌리티 자동 | 모바일은 발열로 성능이 시간에 따라 떨어짐 | 실행 중 프레임 시간을 보고 단계를 내리는 동적 조정 옵션 |

## 🟢 편의성 개선

| 항목 | 내용 |
|---|---|
| **복사 = 텍스트** | 오브젝트나 컴포넌트를 Ctrl+C 하면 클립보드에 JSON 한 줄이 들어감. AI 채팅에 바로 붙여 넣고, 받은 답을 Ctrl+V로 씬에 붙여 넣기 |
| **다중 선택 편집** | 여러 오브젝트를 고르고 Inspector에서 한 번에 수정 (값이 다르면 `—` 표시). 기획에 빠져 있었음 |
| **명령 팔레트** | Ctrl+Shift+P: 메뉴, 명령, 에셋, 설정을 이름으로 검색해 실행. Ctrl+P는 유니티처럼 Play로 유지 |
| **선택 기준 AI 요청창** | 선택한 오브젝트를 문맥으로 붙여 "이거 5개 복제해서 원형으로 배치" 같은 요청 |
| **Play 모드 값 유지** | 정지하면 되돌아가는 게 유니티의 대표 불편. 컴포넌트에서 "값 유지"를 누르면 정지 후에도 적용 |
| **프리팹 필드별 적용·되돌리기** | 오버라이드된 값마다 우클릭으로 "프리팹에 적용 / 되돌리기" |
| **스냅과 정렬** | 그리드 스냅, 표면 스냅, 정렬·분배 도구 |
| **자동 저장과 크래시 복구** | 일정 간격으로 `.user/autosave`에 저장, 비정상 종료 후 복구 제안 |
| **대형 Hierarchy** | 오브젝트가 수천 개여도 버벅이지 않게 가상 스크롤 |
| **에디터 한국어** | 에디터 UI 현지화 (한국어, 영어부터) |
| **프로젝트 템플릿** | 2D 플랫포머, 3D 3인칭, UI 전용 앱 등 시작 템플릿 |

## ➕ 추가할 기능

### AI 안내 파일 자동 생성
- 프로젝트 루트에 `AGENTS.md`(필요하면 `CLAUDE.md`)를 엔진이 만들고 계속 갱신합니다.
- 내용: 이 프로젝트의 기본 언어, 폴더 규칙, `bdg` 명령 요약, 컴포넌트 시그니처 요약, "에디터가 켜져 있으면 명령을 쓸 것" 같은 규칙
- AI가 매번 엔진 사용법을 다시 알아낼 필요가 없어져서 토큰 절약 효과가 큽니다.

### 그 외

| 기능 | 내용 | 시기 |
|---|---|---|
| 자동 테스트 프레임워크 | 단위 테스트 + 플레이 테스트(입력 재생, 조건 검사). `bdg test`의 실체 | MVP |
| 중첩 프리팹과 변형 | 프리팹 안의 프리팹, 변형의 변형까지 규칙 명시 | MVP |
| 에셋 썸네일 헤드리스 생성 | Project 패널 썸네일과 AI용 미리보기를 CLI로 | MVP |
| 텍스트 프로파일러 출력 | `bdg profile --frames 300` → 느린 시스템 상위 10개를 표로. AI가 성능 문제를 직접 진단 | 1.0 |
| 에셋 번들 / 원격 다운로드 | 모바일·웹에서 필요한 에셋만 나중에 받기 (유니티 Addressables 개념) | 1.0 |
| 씬 diff 보기 | 두 버전의 씬을 오브젝트 단위로 비교하는 에디터 화면 | 1.0 |
| 접근성 | UI 글자 크기 배율, 색약 모드, 자막 시스템 | 1.0 |
| 휴지통 | 에셋 삭제를 Undo 가능하게 (`.user/trash`) | MVP |

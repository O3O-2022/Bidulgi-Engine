# 위험과 약점 대응 (2026-11-20)

"비둘기 엔진의 단점" 점검에서 나온 항목을 **빼거나, 고치거나, 보완**한 결정입니다.
설계(인터페이스)는 넓게 유지하고, **1.0 구현 범위만 좁힙니다.** 뺀 기능은 없어진 것이 아니라 1.0 이후로 미룬 것입니다.

---

## 가장 큰 위험

### 1. 범위가 너무 넓음 → 1.0 범위를 잘라냄

| 항목 | 1.0에 넣음 | 1.0 이후로 미룸 (설계는 유지) |
|---|---|---|
| 스크립팅 | **C#**, **그래프**, **Lua**, **C++** 모듈, Python(AI·에디터·도구) | C++ 핫 리로드, 그래프 AOT, Python 게임 실행 (Rust는 2026-11-21 지원 언어에서 제외) |
| 그래픽 백엔드 | **OpenGL 4.5**, **GLES 3.0 / WebGL2** | SDL_GPU(Vulkan·Metal·D3D12), 콘솔 전용 API |
| 플랫폼 | **Windows**, **Android**, **Web** | Linux(쉬움, 1.1 후보), macOS·iOS, 콘솔 |
| 그래프 실행 | **레지스터 VM** + 순수 노드 최적화 + 묶음 실행 | C++ AOT 변환 |
| 애니메이션 | 클립, State Machine, Blend Space, Montage, Notify, 타임라인 | IK 전체, 리타게팅, Graph Editor, Sequencer 컷신 |
| UI | 위젯, Screen/World/Camera, UI Designer | 위젯 그래프 그래프 |
| 그 밖에 | — | VFX, 터레인, 멀티플레이어, 모드 지원 |

- 기준: "1~2명이 1.0까지 만들 수 있는가", "AI 친화라는 정체성에 꼭 필요한가".
- 인터페이스(RHI, C API, 플랫폼 레이어, 리플렉션)는 처음부터 전체 범위를 기준으로 설계해서, 미룬 기능을 나중에 붙일 때 구조를 고치지 않게 합니다.

### 2. 생태계가 없음 → 기존 생태계를 빌려 쓰기

새 엔진이 에셋 스토어와 커뮤니티를 처음부터 키우기는 어렵습니다. 그래서 **이미 있는 것을 그대로 쓸 수 있게** 합니다.

| 방법 | 내용 |
|---|---|
| 열린 표준 우선 | 모델은 glTF·FBX, 텍스처는 PNG·KTX2, 오디오는 WAV·OGG. 다른 엔진용 에셋 대부분을 그대로 가져올 수 있음 |
| 유니티 에셋 가져오기 | `.unitypackage`에서 모델, 텍스처, 오디오, 머티리얼 기본값, 프리팹 계층을 가져오는 임포터 (스크립트는 C#이라 API가 비슷한 부분부터 변환 제안) |
| 블렌더 연동 | 블렌더 애드온: 저장하면 엔진에 자동 반영 |
| AI가 튜토리얼 역할 | AGENTS.md, `bdg explain`, 압축 스키마 덕분에 "이거 어떻게 해?"를 AI가 바로 답하고 실행. 문서 부족을 상당 부분 메움 |
| 템플릿과 예제 | 2D 플랫포머, 3D 3인칭, UI 앱 템플릿. 각 템플릿에 플레이 테스트 포함 |
| 패키지 | 처음에는 스토어 없이 **git 주소로 설치**하는 패키지 (`bdg add-package github.com/...`) |
| 오픈소스 | 엔진을 오픈소스로 공개해 기여자를 모으는 방향을 검토 (라이선스는 미결 사항) |

### 3. 그래프 C++ 변환(AOT)의 어려움 → 1.0에서 빼고, 들어올 때는 검증 장치와 함께

- **1.0은 레지스터 VM만** 씁니다. 순수 노드 결과 재사용, 상수 접기, 같은 그래프 인스턴스 묶음 실행으로 언리얼 VM보다 빠르게 만드는 데 집중합니다.
- 성능이 중요한 부분은 **그래프 → C# 코드 내보내기**로 옮기는 길을 먼저 제공합니다 (사람이 확인할 수 있는 코드라 결과가 투명함).
- AOT는 1.0 이후에 넣고, 넣을 때는 **차등 테스트**를 의무로 둡니다: 모든 그래프 단위 테스트와 플레이 테스트를 VM과 AOT 양쪽에서 돌려 결과가 같아야 빌드가 통과합니다. 다르면 AOT 대신 VM으로 실행하고 경고를 남깁니다.

## 기술적 약점

### 4. 고급 그래픽이 약함 → 경쟁하지 않는 영역을 정하고, 중급 품질을 확실히

- **목표 위치:** 스타일라이즈드, 모바일, 인디 중·고급 그래픽. 언리얼의 나나이트·루멘과 정면 경쟁하지 않습니다.
- 1.0 품질 경로:
  - Forward+ (클러스터 라이트), PBR 머티리얼
  - **라이트맵 + 라이트 프로브 베이크** (모바일·웹에서도 좋은 조명)
  - 그림자: CSM, 소프트 그림자
  - 포스트 프로세스: 톤매핑, Bloom, SSAO, FXAA/TAA, 컬러 그레이딩 LUT
  - 스타일라이즈드용: 툰 셰이딩, 외곽선, 커스텀 포스트 프로세스 노드
- 렌더 그래프가 확장점이라, 고급 기법(SSGI, 볼류메트릭 등)은 패키지로 붙일 수 있게 합니다.
- 편집 중 플랫폼 예산 표시로 "목표 기기에서 잘 돌아가는 그래픽"을 장점으로 내세웁니다.

### 5. 에디터 UI 품질 → 자체 UI 프레임워크 + 창·입력·접근성 계층 보강 (2026-11-21: Dear ImGui 대신 자체 구현)

| 문제 | 보완 |
|---|---|
| **한글 입력(IME)** | 창·입력 계층을 GLFW에서 **SDL3**로 바꿉니다. SDL3는 IME 조합 중 글자 처리, 후보 창 위치 지정을 지원합니다. 에디터의 모든 텍스트 입력은 공통 입력 위젯 하나를 거치게 해서, 조합 중인 글자를 입력칸 안에 바로 그립니다. **M0의 완료 조건에 "한글 입력 테스트 통과"를 넣습니다.** |
| 고해상도 화면 | UI 프레임워크가 모든 크기를 배율 단위로 계산 + 모니터별 DPI 배율, MSDF 글꼴. 디자인 시스템 토큰을 px 대신 배율 기준으로 계산 |
| 스크린 리더 등 접근성 | **AccessKit**(접근성 트리 라이브러리, C 바인딩 제공)으로 패널·버튼·입력칸 정보를 OS에 알림. 키보드만으로 모든 패널 이동 가능하게 |
| 테마 | 어두운 테마 + **밝은 테마**와 **고대비 테마** 추가 (디자인 시스템 토큰에 테마만 추가하면 됨). `fg-faint`처럼 대비가 부족한 색은 고대비 테마에서 보정 |
| 큰 목록 성능 | Hierarchy·Project는 가상 스크롤(보이는 행만 그림) |

SDL3로 바꾸면 덤으로 게임패드, 모바일 터치, 웹(Emscripten) 지원이 한 계층으로 통일되고, 이후 **SDL_GPU**로 Vulkan·Metal·D3D12까지 열 수 있습니다 (7번).

### 6. 언어가 많아서 생기는 비용 → 1.0은 3개 + 공통 도구

- 1.0 언어: **C#(주 언어), 그래프, Lua**. Python은 에디터 자동화 전용이라 게임 실행에 참여하지 않습니다.
- **디버거 통일:** 모든 언어를 **DAP(Debug Adapter Protocol)**로 연결해 VS Code 하나에서 C#·Lua·그래프를 같이 디버깅합니다. 에디터 안 그래프 디버거도 같은 프로토콜을 씁니다.
- **문서 자동 생성:** 리플렉션 정의에서 언어별 API 문서와 예제를 생성합니다.
- **언어 선택 혼란 방지:** 새 프로젝트는 C# 하나만 켜진 상태로 시작합니다. 프로젝트 설정에서 필요한 언어를 켭니다. 에디터의 "새 스크립트" 메뉴는 기본 언어를 맨 위에 둡니다.

### 7. Apple·콘솔 플랫폼 제약 → SDL_GPU 백엔드로 길을 열어 둠

- RHI의 두 번째 백엔드를 직접 Vulkan·Metal·D3D12 세 개로 만들지 않고, **SDL_GPU 하나**로 만듭니다. SDL_GPU가 Vulkan, Metal, D3D12를 감싸 주므로 macOS·iOS와 고사양 PC를 한 번에 엽니다.
- 셰이더는 한 언어(HLSL 또는 GLSL)로 쓰고, 빌드 때 SPIR-V / MSL / DXIL로 변환합니다 (SDL_shadercross 계열 도구).
- 콘솔은 제조사 계약이 필요한 것은 그대로입니다. 다만 SDL은 콘솔용 비공개 포트가 있어, 계약을 맺으면 플랫폼 계층을 처음부터 만들지 않아도 됩니다.

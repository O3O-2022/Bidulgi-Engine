## 1. 빌드 실패를 설명하는 빌드

- **빌드 전 사전 검사** `bdg build --check` (빌드 창의 "검사" 버튼): 깨진 참조, 없는 파일, 플랫폼에서 지원하지 않는 텍스처 형식, 셰이더 컴파일 오류, 스크립트 컴파일 오류, 서명 키 누락을 **쿠킹 전에** 모두 찾아 목록으로 보여 줌.
- **단계마다 격리된 오류**: collect → cook → scripts → pack → output 중 **어느 단계, 어느 에셋에서, 왜** 실패했는지 한 줄로. 수천 줄 로그를 뒤질 필요 없음.
  ```
  ✗ [2/5] cook  Textures/T_Wall_N.png
     원인: 2049x2048 — ASTC는 블록 크기 배수가 필요
     고치기: 크기를 2048x2048로 (bdg fix T_Wall_N --resize)   또는 이 플랫폼에서 압축 형식 변경
  ```
- **실패해도 멈추지 않고 끝까지**: 오류를 모두 모아 한 번에 보여 줌(첫 오류에서 멈추지 않음).
- **증분·재현 가능**: 같은 입력이면 같은 결과(해시 캐시). "어제는 됐는데 오늘 안 됨"을 줄임.
- **CI가 커밋마다 빌드**: 실패를 출시 직전이 아니라 그 커밋에서 발견.
- **AI가 읽는 보고서**: `build-report.txt`의 오류 형식이 고정돼 있어 AI가 바로 고칠 수 있음.

## 2. 열다가 튕기지 않는 에셋 (에디터 안전장치)

- **텍스트 저장**: 그래프가 망가져도 텍스트 편집기로 열어 고치거나, `bdg validate Door.graph --fix`로 깨진 연결만 제거. 파일을 지울 필요가 없음.
- **열기 전에 검사**: 그래프·씬을 불러올 때 먼저 구조 검사(없는 노드 타입, 끊긴 연결, 순환 참조). 문제 노드는 빨간 "깨진 노드"로 표시하고 나머지는 정상으로 엶.
- **VM 보호**: Graph VM에 명령 수 예산(한 프레임 기본 1천만), 호출 깊이 제한, 메모리 제한. 넘으면 그 그래프만 멈추고 오류 위치(노드)를 강조. 에디터는 계속 동작.
- **Construction Script는 에디터에서 제한 시간**: 배치할 때 실행되는 스크립트가 오래 걸리면 중단하고 경고.
- **안전 모드 재시작**: 에셋을 여는 중에 크래시가 나면, 다음 실행 때 "마지막에 연 `Door.graph` 때문에 종료된 것 같아요" → 그 에셋을 **격리(열지 않음)** 한 채 에디터를 엶. 크래시 보고서도 같이 만듦.
- **자동 저장·복구**와 연결: 튕겨도 작업이 날아가지 않음.

## 7. 파이썬처럼 기다리기 (모든 언어)

언리얼 C++에서 "2초 뒤에 폭발"은 이렇게 길어집니다.
```cpp
// 언리얼
FTimerHandle Handle;
GetWorldTimerManager().SetTimer(Handle, FTimerDelegate::CreateLambda([this]() {
    if (IsValid(this)) Explode();          // 이걸 빼먹으면 크래시
}), 2.0f, false);
```
비둘기 엔진은 **C++20 코루틴**으로 파이썬·C#과 같은 모양입니다.
```cpp
// 비둘기 엔진 C++
BTask BBomb::Start()
{
    co_await Wait(2.f);                     // 2초 기다림
    Explode();
    co_await WaitUntil([this] { return Target && Target->IsDead(); });   // 조건이 될 때까지
    auto Hit = co_await WaitForEvent<FOnHit>(5.f);                      // 이벤트 기다리기 (5초 제한)
    if (!Hit) Log("시간 초과");
}
```
```python
# 참고: 파이썬 (디스코드 봇에서 쓰던 방식)
await asyncio.sleep(2)
```
| 같은 일 | C++ | C# | Lua | Graph |
|---|---|---|---|---|
| 2초 기다리기 | `co_await Wait(2.f)` | `await Wait(2)` | `wait(2)` | Wait 노드 |
| 조건까지 | `co_await WaitUntil(f)` | `await WaitUntil(() => …)` | `waitUntil(f)` | Wait Until |
| 다음 프레임 | `co_await NextFrame()` | `await NextFrame()` | `wait()` | Next Frame |
| 2초 뒤 한 번 (콜백) | `After(2.f, [&]{…})` | `After(2, …)` | `After(2, f)` | After |

**크래시를 막는 규칙 (언리얼 타이머의 함정 제거):**
- 코루틴과 타이머는 **시작한 오브젝트에 묶임**. 오브젝트가 지워지면 대기 중인 코루틴은 자동 취소 — `this`가 사라진 뒤 실행되는 일이 없음.
- 씬 전환·플레이 모드 종료 때도 자동 취소. 일시 정지(`Time.scale = 0`)에는 멈춤(옵션으로 실제 시간 기준 `WaitRealtime`).
- 모든 코루틴은 게임 스레드에서 재개 (스레드 안전 걱정 없음). 무거운 작업은 `co_await RunOnWorker(f)`로 명시적으로 넘김.
- 취소 핸들: `auto t = Every(1.f, f); t.Cancel();`

## 8. 잘 죽지 않는 엔진

| 언리얼에서 크래시 나는 경우 | 비둘기 엔진 |
|---|---|
| 지워진 오브젝트 포인터 접근 (GC 이후) | 모든 언어에서 **핸들**(세대 번호) 사용. 지워진 대상에 접근하면 크래시 대신 경고 + 아무 일도 안 함, `IsValid()`·`if (!obj)` |
| 널 포인터 | 엔진 API는 널을 받으면 경고 로그 후 안전하게 반환 (배포 빌드에서도). `[Auto]` 연결 실패는 시작할 때 경고 |
| `check()` / `ensure` 실패로 에디터 종료 | 에디터에서는 **복구 가능한 오류로 처리**: 해당 시스템만 멈추고 에디터·작업은 유지, 보고서 생성. 진짜 메모리 손상이 의심될 때만 안전 종료(자동 저장 후) |
| 스크립트 오류가 에디터를 죽임 | C#·Lua·Graph 오류는 **그 스크립트만 정지**, 오류 줄로 이동. 플레이 모드만 멈춤 |
| C++ 모듈의 잘못된 메모리 접근 | 에디터에서 모듈 호출을 **SEH 가드**로 감싸 예외를 잡고, 그 모듈을 비활성화 + 자동 저장 + 크래시 보고서. 완전한 보호는 불가능하므로(메모리 손상) 바로 다음 실행에서 안전 모드 제안 |
| 에셋을 열다 크래시 | 열기 전 검사 + 안전 모드 격리 (2번 항목) |
| 크래시 후 작업 손실 | 자동 저장·복구, 크래시 보고서(crashpad) |

**품질 장치:**
- CI에 **AddressSanitizer(ASan) 빌드** 추가: 메모리 오류를 출시 전에 잡음.
- **퍼징**: 씬·그래프·머티리얼 로더에 무작위로 깨진 파일을 넣어도 크래시 없이 오류만 내는지 자동 검사.
- **오류 주입 테스트 모음**: 널 접근, 무한 루프, 지워진 오브젝트 접근, 예외 던지는 스크립트 → 에디터가 살아 있어야 통과.

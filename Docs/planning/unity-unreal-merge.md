# 유니티 + 언리얼 혼합에서 생기는 문제와 정답

작성 2026-11-21. 엔진 목표는 **유연하고 편한 엔진**입니다.

## 원칙

1. **개념마다 정답은 하나.** 두 엔진 방식을 동시에 지원하지 않습니다. 다른 엔진 방식은 이름 대응표, 별칭, 프리셋으로만 제공합니다.
2. **기본은 단순하게, 깊이는 선택으로.** 고급 기능은 패키지나 템플릿으로 켭니다.
3. **바꾸기 어려운 것부터 확정.** 게임 구조, 생명주기 이름, 좌표·단위는 코드를 쓰기 전에 정합니다 (M0 이전).

## 충돌 목록과 결정 (제안)

| # | 충돌 | 문제 | 정답 (제안) | 확정 시점 |
|---|---|---|---|---|
| 1 | **게임 구조** | 유니티 GameObject + 컴포넌트 vs 언리얼 Actor·Pawn·Controller·GameMode. 둘 다 있으면 코드 위치가 애매함 | 기본은 **컴포넌트 방식**. GameMode·PlayerController·Pawn은 선택형 템플릿 프리팹과 컴포넌트로 제공 | M0 전 |
| 2 | **프리팹 vs 블루프린트 클래스** | 언리얼은 블루프린트가 클래스이자 프리팹, 유니티는 데이터와 코드 분리 | **Graph는 컴포넌트(스크립트)**, 프리팹은 데이터만. 로직 위치가 항상 한 곳 | M0 전 |
| 3 | **생명주기 이름** | C# `Start`/`Update`, C++ `BeginPlay`/`Tick`처럼 같은 개념에 두 이름 | **확정 (2026-11-21): 유니티식** `Awake` `Start` `Update(dt)` `FixedUpdate(dt)` `LateUpdate(dt)` `OnEnable` `OnDisable` `OnDestroy`. C++ 포함 모든 언어가 같은 이름. `BeginPlay`·`Tick` 등은 대응표와 검색 별칭으로만 | ✅ 확정 |
| 4 | **좌표·단위** | 유니티 Y-up·m vs 언리얼 Z-up·cm. 섞이면 임포트·물리·애니메이션이 꼬임 | **Y-up, 1단위 = 1m** (glTF와 같음). 임포트 때 축·단위 자동 변환, 변환 내역은 `.meta`에 기록 | M0 전 |
| 5 | **에셋 참조** | 유니티 GUID vs 언리얼 경로 참조. 하드 참조 남발 시 전부 로드되는 문제 | GUID가 기본. 필요할 때 로드하는 **소프트 참조**는 별도 타입(`SoftRef<T>`)으로 명시. `bdg refs`로 로드 사슬을 텍스트로 확인 | M2 |
| 6 | **플레이 모드** | 유니티는 정지 시 변경이 사라짐(불만 많음), 언리얼은 복사 월드 | 플레이용 **복사본 월드**. 플레이 중 바꾼 값은 "이 변경 유지"로 골라서 원본에 반영 (명령 버스로 Undo 가능) | M3 |
| 7 | **오브젝트 수명** | 유니티 가짜 null, 언리얼 UObject GC. 언어 5개에서 더 꼬일 수 있음 | 모든 언어에서 **핸들** 참조, 유효성은 `IsValid()` 하나. 파괴된 대상 접근은 언어와 무관하게 같은 오류 메시지 | M1 |
| 8 | **언어가 많음** | 같은 기능을 5가지로 만들 수 있어 예제·패키지·협업이 쪼개짐 | **권장 경로: C# + Graph.** C++는 성능·엔진 확장, Lua는 모드·핫픽스, Python은 에디터·도구·AI. 공식 예제는 권장 경로로 먼저 | 문서화 |
| 9 | **복잡도 유입** | 언리얼급 기능(월드 파티션, 능력 시스템 등)이 기본 화면을 무겁게 함 | 고급 기능은 **패키지로 켬.** 새 프로젝트 템플릿(2D, 3D, 오픈월드, 멀티플레이)마다 기본으로 켜진 기능이 다름 | M6 |
| 10 | **단축키·조작** | 양쪽 사용자 모두 어중간하다고 느낄 수 있음 | 기본은 유니티 단축키 + **언리얼 프리셋**. 첫 실행 때 선택, 언제든 변경 | M1 |
| 11 | **컴파일 대기** | 유니티 도메인 리로드 + 언리얼 C++ 빌드 대기를 둘 다 가져올 위험 | C# 핫 리로드, C++ 모듈 단위 라이브 리로드. 목표 시간(예: C# 변경 → 반영 2초)을 CI에서 측정 | M4 |
| 12 | **물리 시간** | 유니티 FixedUpdate vs 언리얼 서브스텝 | 고정 스텝 하나(`FixedUpdate`에 해당) + 렌더 보간. 서브스텝은 물리 백엔드 내부 설정 | M6 |

> 입력(입력 액션으로 통일)과 애니메이션(애니메이션 그래프)은 이미 정했습니다 → [input](../features/input.md), [animation](../features/animation.md).

## 다른 엔진 사용자를 위한 장치

- **이름 대응표:** 문서와 에디터 검색에서 `Tick`, `BeginPlay`, `Instantiate`, `SpawnActor` 같은 다른 엔진 이름을 치면 이 엔진의 이름으로 안내합니다.
- **임포터:** 유니티 프로젝트·에셋 임포터(이미 계획), 언리얼은 FBX·glTF 내보내기 경로를 안내합니다.
- **AI 안내:** AGENTS.md에 대응표를 넣어, AI가 유니티·언리얼 습관대로 코드를 써도 이 엔진 방식으로 고쳐 쓰게 합니다.

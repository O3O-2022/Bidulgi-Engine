# 에디터 UI 검토 (2026-11-26, 1단계: 분석)

사용성, 읽기 쉬움, 배치, 크기, 스타일을 화면을 찍고 위젯 덤프로 재서 검토했습니다. 이 문서는 **분석과 제안만** 담습니다. 코드는 2단계에서 고칩니다(레인 A가 UI Designer를 마친 뒤). 기준은 [디자인 시스템](../../design-system/project/README.md)과 유니티·언리얼의 같은 작업입니다.

심각도: **높음** = 기능이 없거나 거짓 정보(죽은 버튼, 가짜 내용) · **중간** = 쓰기 불편하거나 규칙 위반이 넓게 퍼짐 · **낮음** = 다듬기.

## 어떻게 쟀나

- 에디터(Release, 3c9e088 + 1a3998c)를 숨긴 창으로 띄워 `BDG_SCREENSHOT` + `BDG_DUMP_WIDGETS`로 찍었습니다. 창 1280×720 / 1920×1080 px × UI 배율 1 / 1.5 / 2, 워크스페이스 탭 5개(`BDG_WORKSPACE`), Inspector(Light, MeshRenderer+Rigidbody, Animator, PostProcessVolume, UICanvas, UIElement, Terrain, Camera, WorldSettings — `BDG_SELECT`), 아래 도크 탭 5개(`BDG_DOCK_TAB`), Project Settings, 종료 확인 대화상자, 버튼 클릭·우클릭·호버.
- 화면은 저장소에 넣지 않았습니다. 파일 이름(아래 "화면")은 레인 B 작업 폴더 `scratchpad/ui/`의 PNG·JSONL입니다. 다시 찍으려면 아래 "다시 재기"를 봅니다.
- 덤프에는 원래 위치·크기만 있어서, 검토하는 동안만 글자·툴팁·숨김·선호 크기·핸들러 여부를 덤프에 더하고(UI.cpp `DumpJSONL`) 클릭·우클릭·호버를 넣는 임시 검사(assets.inl)를 썼습니다. 둘 다 커밋하지 않았습니다 — 2단계에서 덤프 확장은 정식으로 넣는 것을 권합니다(B13).
- 대비는 `--dump-tokens`의 실제 토큰 값으로 WCAG 2.x 식을 계산했습니다(본문 4.5:1, 큰 글자·조작 요소 경계 3:1).

크기 표기는 모두 **UI 단위**(배율 1에서 px)입니다. 기본 화면(이 PC: 표시 배율 1.5, 창 1920×1080 px)은 1280×720 UI 단위입니다.

### U1. 메뉴바 전체가 동작하지 않음 — 높음
- **화면:** `size-1920x1080-s1.png` (File … Help)
- **무엇:** 메뉴 8개가 `DimLabel`로만 만들어져 클릭 핸들러가 없습니다(`Engine/Runtime/Screens.cpp:257`). 클릭해도 아무 일도 없습니다. 유니티·언리얼 사용자가 가장 먼저 찾는 곳입니다.
- **고칠 곳:** `Screens.cpp` 메뉴바 생성, `Engine.cpp`에서 명령 연결.
- **제안:** 메뉴 이름을 버튼(높이 24, 좌우 `space-5`, 호버 `raise` 바탕)으로 바꾸고 클릭하면 `UIContext::OpenMenu`. 항목 옆에 기존 단축키 표(`shortcut.*`)의 키를 오른쪽 정렬로 표시.
  - File: 새 장면 (Ctrl+N), 장면 열기…, 저장 (Ctrl+S), 모두 저장 (Ctrl+Shift+S), 종료 (Ctrl+Q)
  - Edit: 실행 취소, 다시 실행, 복제, 삭제, 이름 바꾸기, Project Settings…
  - Assets: 가져오기…, 새 폴더, 새 C# 스크립트, 새 머티리얼
  - GameObject: 빈 오브젝트 (Ctrl+Shift+N), 3D 도형 ▸, 라이트 ▸, 카메라, UI ▸ (U3와 같은 목록)
  - Component: 컴포넌트 추가… (U2 팝업)
  - Build: 빌드, 검사만
  - Window: 패널 열기 ▸(Hierarchy, Inspector, Project, Console, Profiler, History)
  - Help: 갤러리 (F1), 문서, 버그 제보 (Ctrl+Shift+B)
- **유니티·언리얼:** 둘 다 메뉴에서 거의 모든 기능에 닿습니다.

### U2. "Add Component" 버튼이 아무것도 하지 않음 — 높음
- **화면:** `click-addcomp.png` (클릭 뒤에도 변화 없음)
- **무엇:** `MakeButton("insp.add", "+  Add Component")`에 `onClick`이 없습니다(`Engine/Runtime/EditorModel.cpp:1005`). 컴포넌트를 붙이는 길은 "+ 물리 추가"(Rigidbody+Collider)와 다른 오브젝트의 컴포넌트 "값 복사 → + 붙여넣기"뿐입니다.
- **고칠 곳:** `EditorModel.cpp` Inspector 아래 버튼 줄.
- **제안:** 클릭하면 검색이 있는 메뉴(`OpenMenu(..., search=true)`). 등록된 컴포넌트 전부를 분류(렌더링 / 물리 / 오디오 / UI / 애니메이션 / 스크립트(C#·C++))로 묶습니다. 이미 붙은 것은 회색(`enabled=false`). 너비는 버튼 너비 이상 최소 280, 높이 최대 420. 입력하면 바로 거르고 Enter로 추가(`addcomp` 명령, 한 번의 실행 취소). 버튼 글자는 "+ 컴포넌트 추가"(U12 참고).
- **클릭 수:** 유니티 2번 + 입력(Add Component → 검색 → Enter). 지금 비둘기는 **불가능**(복사·붙여넣기로 4번).

### U4. Console·Build Log가 고정된 가짜 줄 — 높음
- **화면:** `dock1.png` (Console), `dock2.png` (Build Log)
- **무엇:** `Screens.cpp`의 아래 도크 그리기에서 `static const Line console[]`, `build[]` 배열을 그립니다("quest.lua:12 attempt to index nil value 'npc'", "PlayerMove.cs compiled in 0.42 s", "[5/5] done Bin/MyGame.exe"). 실제 로그(`LogError` 4줄을 넣어 봄)는 보이지 않습니다. 사용자가 없는 오류를 고치려 하거나 진짜 오류를 놓칩니다.
- **고칠 곳:** `Screens.cpp` 아래 도크 탭 1·2, `Core/Log`(줄을 모으는 수신자).
- **제안:** 로그 수신자가 최근 2000줄을 링 버퍼로 보관 → 가상 스크롤 목록(줄 높이 `size-row` 22, 글자 `code` 12, mono). 위 도구줄(높이 30):
  - 검색칸(최소 160)
  - 정보 n / 경고 n / 오류 n 토글 배지
  - 지우기, 자동 스크롤
  
  오류 줄은 지금처럼 `err` 10 % 바탕. `파일:줄`이 있는 줄은 더블클릭하면 그 파일을 엽니다. 줄 우클릭 메뉴는 복사, 모두 복사. Build Log는 `bdg build` 출력 줄을 같은 목록에 보여 줍니다.

## 다시 재기

1. 덤프 확장(B13)을 넣거나, 이 검토 때처럼 임시로 `DumpJSONL`에 `text, text2, tip, items, hidden, prefW, prefH, pad, gap, click, ctx, drag, drop, focusable, primary`를 더합니다.
2. 창 크기: `--size`는 UI 단위이고 표시 배율(이 PC 1.5)만큼 커집니다. 1920×1080 px를 얻으려면 `--size 1280x720`, 1280×720 px는 `--size 853x480`을 씁니다. UI 배율은 `BDG_UI_SCALE`입니다.
3. 캡처 한 장: `BDG_SCREENSHOT`, `BDG_DUMP_WIDGETS`, `BDG_LAYOUT=ci-layout-none.jsonl`, `BDG_SCENE_FILE`, `BDG_SELECT`, `BDG_WORKSPACE`, `BDG_DOCK_TAB`, `--frames 14`. 그 뒤 덤프를 `analyze.py`(작은 대상, 잘린 글자, 겹침, 부모 밖, 툴팁 없는 아이콘 버튼, 종류별 높이)로 셉니다.
4. 대비: `BidulgiEditor --dump-tokens tokens.json` → 글자 토큰 × 바탕 토큰 표.

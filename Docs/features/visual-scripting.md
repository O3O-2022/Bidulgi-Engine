# 비주얼 스크립팅 (그래프)

목표: **언리얼 블루프린트의 문제를 고친, 훨씬 빠른 차세대 그래프.**
언리얼 사용자가 바로 쓸 수 있도록 구조와 개념은 그대로 두고, 고질적인 문제를 설계 단계에서 고칩니다. 화면은 언리얼을 흉내 내지 않고 비둘기 엔진 에디터와 같은 스타일(자체 UI 프레임워크)로 통일합니다.

> 이름: 언리얼(Epic)의 "블루프린트"와 겹치지 않도록 **그래프(Graph)**라고 부릅니다 (2026-11-21 확정). 파일은 `.graph`, 애니메이션은 `.animgraph`입니다. 엔진 이름이 정해지면 "<엔진 이름> 그래프"처럼 붙여 쓸 수 있습니다.

## 언리얼과 같은 구조

| 요소 | 내용 |
|---|---|
| Blueprint Class | 부모 클래스(`Behaviour`, `GameObject`, 다른 그래프)를 상속하는 클래스 |
| Components 패널 | 그래프에 붙은 컴포넌트 트리 |
| Event Graph | `Start`, `Update`, `OnCollisionEnter`, 입력 이벤트 등에서 시작하는 실행 흐름 |
| Construction Script | 에디터에서 배치하거나 값을 바꿀 때 실행 (절차적 배치용) |
| Functions / Macros | 재사용 그래프. 순수(pure) 함수와 실행(impure) 함수 구분 |
| Variables | 타입, 기본값, Inspector 노출 여부, 카테고리 |
| Event Dispatchers | 다른 그래프가 구독하는 이벤트 |
| Interfaces | 그래프 인터페이스 (캐스팅 없이 메시지 전달) |
| Scene Graph | 씬 하나에 붙는 그래프 (언리얼 Level Blueprint) |
| Function / Macro Library | 프로젝트 공용 노드 모음 |
| Data-only Blueprint | 그래프 없이 값만 바꾼 자식 클래스 |

### 노드 종류

- **이벤트:** Start, Update, Fixed Update, 충돌/트리거, 입력 액션, 커스텀 이벤트
- **흐름 제어:** Branch, Sequence, For / ForEach / While, Switch, Gate, DoOnce, FlipFlop, Select
- **지연(latent):** Delay, Timeline(그래프 안의 작은 커브 애니메이션), Async 작업 대기
- **데이터:** 변수 Get/Set, Cast, Make/Break 구조체, 배열·맵 조작
- **수식 노드:** `a * 2 + b` 같은 식을 노드 하나로 (와이어 줄이기)
- **정리:** Comment 상자, Reroute 점, 접기(Collapse to Function)

## 언리얼 블루프린트의 문제와 해결

| # | 언리얼의 문제 | 비둘기 엔진의 해결 |
|---|---|---|
| 1 | **느림.** 스택 VM이 노드마다 함수를 호출. C++ 변환(Nativization)은 UE5에서 제거됨 | 레지스터 VM + 빌드 때 C++ AOT 컴파일 ([업그레이드 1](#업그레이드-1-실행-속도)) |
| 2 | **순수 노드 반복 계산.** 순수 노드는 연결된 핀이 읽힐 때마다 다시 실행됨 (반복문 안에서 특히 비쌈) | 순수 노드 결과를 실행 단위로 한 번만 계산해 재사용. 다시 계산이 필요하면 `Recompute` 표시를 명시 |
| 3 | **바이너리 저장.** diff·병합 불가, 팀 충돌, AI가 못 읽음 | 텍스트 저장, 노드 단위 diff, id 기준 병합 ([업그레이드 2](#업그레이드-2-텍스트-저장과-ai-편집)) |
| 4 | **하드 참조 연쇄 로딩.** Cast 노드 하나가 대상 그래프와 그 에셋 전체를 메모리에 올림 | 인터페이스·소프트 참조를 기본 권장, Cast는 대상의 **타입 정보만** 참조. 에디터가 그래프별 "같이 로드되는 에셋 크기"를 표시 |
| 5 | **Cast 남용.** "Cast To ..." 사슬로 의존성이 얽힘 | 언어를 넘는 인터페이스와 `TryGet<T>` 노드. Cast가 3단 이상 이어지면 경고와 함께 인터페이스로 바꾸는 리팩터링 제안 |
| 6 | **스파게티 와이어.** 큰 그래프를 읽기 어려움 | 자동 정렬, 와이어 묶음, 의사코드 보기, **수식 노드**(`a * 2 + b`를 노드 하나로), 지역 변수(Event Graph에서도 사용 가능) |
| 7 | **Tick 남용.** 모든 그래프가 매 프레임 실행되기 쉬움 | 이벤트 기반을 기본값으로, Tick은 명시적으로 켜고 간격 설정. 화면 밖 Tick 생략, 같은 그래프 인스턴스 묶음 실행 |
| 8 | **실행 중에야 드러나는 에러.** None 접근, 잘못된 형변환이 실행해야 보임 | 정적 타입 검사 강화: 비어 있을 수 있는 참조(`Ref?`)는 확인 노드 없이 쓰면 컴파일 경고. 스레드 규칙 위반은 컴파일 에러 |
| 9 | **함수 안에서 지연 노드(Delay) 불가**, 매크로 공유가 불편 | 비동기 함수(`async`) 지원: 함수 안에서 Delay·대기 사용 가능. 매크로를 라이브러리로 공유하고 버전 관리 |
| 10 | **순환 참조로 컴파일 꼬임** | 그래프 간 의존 그래프를 계산해 순환을 컴파일 전에 표시, 인터페이스로 끊는 방법 제안 |
| 11 | **리팩터링이 어려움.** 변수·함수 이름 변경이 다른 그래프에 잘 전파되지 않음 | 리플렉션 레지스트리 기준 일괄 이름 변경 (그래프, 코드 프록시, 씬 JSON, 애니메이션 참조까지) |
| 12 | **디버깅 한계.** 브레이크포인트 위주, 지난 흐름을 다시 볼 수 없음 | 실행 기록 되감기, 와이어 값 기록, 언어를 넘는 호출 스택 |
| 13 | **코드로 옮기기 어려움** | 그래프 → C# 코드 내보내기 |

## 업그레이드 1: 실행 속도

언리얼 블루프린트는 스택 기반 VM이 노드마다 함수를 호출하는 구조라 느리고, UE5에서는 C++ 변환(Nativization)도 없어졌습니다. 이 엔진은 처음부터 **컴파일러 구조**로 만듭니다.

```
그래프(텍스트) ─▶ 타입 검사 ─▶ IR(SSA) ─▶ 최적화 ─┬─▶ 에디터: 레지스터 기반 바이트코드 VM (즉시 핫 리로드)
                                              └─▶ 빌드:  C++ 코드 생성 → 네이티브 컴파일 (AOT)
```

| 기법 | 효과 |
|---|---|
| 레지스터 기반 VM | 스택 VM보다 명령 수와 메모리 이동이 적음 |
| 순수 노드 최적화 | 상수 접기, 인라이닝, 같은 입력의 순수 노드 결과 재사용 |
| 정적 타입 | 실행 중 타입 확인 없음. 에러는 컴파일 때 |
| **AOT 네이티브 컴파일** | 빌드에서는 그래프가 C++로 바뀌어 손으로 쓴 코드에 가까운 속도 |
| 배치 실행 | 같은 그래프 인스턴스 수천 개의 Update를 한 번에 (데이터를 배열로 모아 실행) |
| Tick 관리 | 이벤트 기반을 기본으로 권장, Tick 간격·그룹 설정, 화면 밖에서 Tick 생략 옵션 |
| 병렬 평가 | 부작용 없는 순수 함수 그래프는 워커 스레드에서 실행 가능 |

**성능 목표 (측정으로 확인할 목표치):** 빌드에서는 같은 로직의 C# 스크립트와 비슷한 속도, 에디터 VM은 그보다 몇 배 이내.

> **1.0은 레지스터 VM만** 씁니다. C++ AOT는 1.0 이후에 넣고, 넣을 때는 모든 그래프 테스트를 VM과 AOT 양쪽에서 돌려 결과가 같아야 통과하는 **차등 테스트**를 의무로 둡니다. 그 전까지 성능이 중요한 부분은 그래프 → C# 코드 내보내기로 옮깁니다. → [risk-response](../planning/risk-response.md#3-그래프-c-변환aot의-어려움--10에서-빼고-들어올-때는-검증-장치와-함께)

## 업그레이드 2: 텍스트 저장과 AI 편집

언리얼 블루프린트는 바이너리(`.uasset`)라서 git diff·병합이 안 되고 AI가 읽을 수 없습니다. 이 엔진의 그래프는 **텍스트**입니다.

```jsonc
// scripts/BP_Goblin.graph
{"v":1, "class":"BP_Goblin", "parent":"Behaviour",
 "vars":{
   "hp":     {"type":"float", "default":100, "edit":true},
   "target": {"type":"ref<GameObject>", "edit":true},
   "speed":  {"type":"float", "default":2, "edit":true}},
 "graphs":{"Event":[
   {"id":"upd",  "op":"Event.Update"},
   {"id":"dist", "op":"Vector.Distance", "in":{"a":"self.pos", "b":"target.pos"}},
   {"id":"near", "op":"Math.Less", "in":{"a":"dist", "b":2.0}},
   {"id":"br",   "op":"Branch", "after":"upd", "in":{"cond":"near"}, "true":"atk", "false":"mv"},
   {"id":"atk",  "op":"Self.Attack"},
   {"id":"mv",   "op":"Transform.MoveTowards", "in":{"target":"target.pos", "speed":"speed"}}
 ]},
 "layout":{"upd":[0,0], "br":[260,0], "atk":[520,-80], "mv":[520,80]}}
```

### 규칙

- 노드 하나 = 한 줄. 다른 노드 출력은 id로(`"dist"`, 특정 핀은 `"dist.out"`), 변수는 이름으로, 상수는 값 그대로
- 실행 흐름: `after`(이전 노드), `then` / `true` / `false` 같은 출력 실행 핀
- **`layout`은 선택.** AI가 좌표 없이 노드만 써도 에디터가 자동 정렬합니다. 사람이 옮긴 좌표만 저장
- `op`는 리플렉션에 등록된 함수 이름. `bdg schema --nodes`로 목록 확인

### 압축 보기 (`bdg graph view`)

AI가 읽을 때는 그래프를 의사코드로 보여 줍니다.

```
BP_Goblin : Behaviour
vars  hp:float=100  target:ref<GameObject>  speed:float=2
on Update:
  if Distance(self.pos, target.pos) < 2:
    Attack()
  else:
    MoveTowards(target.pos, speed)
```

- 반대로 이 의사코드 형식으로 쓰면 그래프로 변환하는 기능도 제공합니다 (`bdg graph from-text`). AI가 그래프를 만드는 가장 짧은 방법입니다.

## 업그레이드 3: 편의성

| 기능 | 내용 |
|---|---|
| 모든 언어의 함수가 노드로 | C# `[Callable]`, C++ `BFUNCTION(Callable)`, Lua·Python export 함수가 자동으로 노드가 됨 (리플렉션) |
| 그래프 diff | 두 버전을 겹쳐서 추가(초록)·삭제(빨강)·변경(노랑) 노드 표시 |
| 디버깅 | 브레이크포인트, 와이어 위 현재 값 표시, 실행 흐름 애니메이션, **최근 N프레임 실행 기록 되감기** |
| 노드 검색 | 이름·설명·태그로 검색, 연결 중인 핀 타입에 맞는 노드만 표시 |
| AI 노드 제안 | "적이 가까우면 공격"이라고 입력하면 노드 묶음 초안 생성 (사람이 확인 후 배치) |
| 자동 정렬 | 선택한 노드를 깔끔하게 정렬 |
| 코드로 내보내기 | 그래프를 C# 코드로 변환 (그래프로 시작해서 코드로 옮겨 갈 때) |

## 그래프 에디터 UI: 엔진 UI 프레임워크로 통일

그래프, 애니메이션 그래프, 머티리얼 그래프는 **하나의 그래프 에디터**를 씁니다. 언리얼의 화면을 흉내 내지 않고, 비둘기 엔진 에디터와 같은 UI 프레임워크와 스타일로 만듭니다.

### 구현

| 항목 | 선택 |
|---|---|
| UI | 자체 UI 프레임워크 (에디터 전체·게임 UI와 공용) |
| 노드 그래프 | **자체 노드 그래프 위젯**: 줌·팬·박스 선택·와이어 그리기·자동 정렬·미니맵. 노드는 디자인 시스템의 Node 부품 |
| 성능 목표 | 노드 5,000개 그래프에서 60fps (화면 밖 노드는 그리지 않음) |
| 테마 | 에디터와 같은 색 토큰 사용. 별도 그래프 전용 테마 없음 |

### 스타일 규칙 (에디터 테마와 통일)

| 요소 | 규칙 |
|---|---|
| 노드 몸체 | 패널과 같은 바탕색, 1px 테두리, 모서리 4px. 그라데이션·광택 없음 |
| 노드 머리 | 얇은 색 띠(3px)로 종류 표시 + 패널 색 머리글. 언리얼식 진한 그라데이션 머리 대신 |
| 노드 종류 색 | 이벤트 = 빨강, 함수 = 파랑, 순수 = 초록, 흐름 제어 = 회색, 변수 = 핀 색 (에디터 강조색과 겹치지 않게) |
| 핀 색 | 타입별 색은 [interop 타입 매핑](../architecture/interop.md#6-타입-매핑)과 같음 |
| 선택 | 에디터 공통 강조색(호박색) 테두리 |
| 글꼴 | 에디터와 같은 글꼴, 같은 크기 단계 |
| 와이어 | 실행 와이어는 굵게(흰색), 데이터 와이어는 핀 색. 실행 중에는 흐르는 점 애니메이션 |

### 화면 구성

```
┌ My Blueprint ─┬ [Compile ✓] [Diff] [Find] [Debug]  실행: VM ▾ ─────────┬ Details ─────┐
│ Graphs        │ BP_Goblin › EventGraph                               │ 선택한 노드·  │
│ Functions     │                                                      │ 변수 속성     │
│ Variables     │        (그래프 캔버스, 그리드, 미니맵)                  │              │
│ Dispatchers   │                                                      │              │
│ Interfaces    ├ [Text (.graph)] [의사코드] [Compiler Results] ───────────┤              │
└───────────────┴──────────────────────────────────────────────────────┴──────────────┘
```

- 패널 배치는 언리얼과 같아서 익숙하고, 겉모양은 엔진 다른 화면과 같습니다.
- 캔버스 아래 Text 탭에서 지금 그래프가 어떤 텍스트로 저장되는지 바로 봅니다.

## 다른 시스템과의 관계

> 코드와 서로 부르는 방법(상속, 함수·변수·이벤트 노출, 인터페이스, 생성되는 프록시)은 [interop](../architecture/interop.md)에 정리했습니다.

- 그래프는 스크립팅 언어 중 하나로 취급됩니다. C API와 리플렉션을 똑같이 사용 → [scripting](../architecture/scripting.md)
- 씬에서는 다른 스크립트처럼 컴포넌트로 붙습니다: `"BP_Goblin":{"hp":50}`
- 애니메이션 그래프는 같은 그래프 엔진 위에 만듭니다 → [animation](animation.md)

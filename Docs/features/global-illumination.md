# 전역 조명 (GI) — 루멘을 넘어서는 목표

가칭: **Halo GI**

## 목표를 숫자로

"루멘보다 뛰어나다"를 막연한 말로 두지 않고, 루멘의 알려진 약점을 하나씩 **측정할 수 있는 목표**로 바꿉니다.

| 루멘의 약점 (일반적으로 알려진 것) | Halo GI 목표 | 측정 방법 |
|---|---|---|
| 노이즈, 움직일 때 잔상(고스팅) | 시간 누적에 덜 의존하는 구조로 잔상 최소화 | 카메라·광원 이동 테스트 장면에서 프레임 간 오차 측정 |
| 조명이 바뀔 때 반응이 느림 | 문을 열거나 불을 켜면 **수 프레임 안에** 반영 | 광원 켜기 테스트: 최종값의 90%에 도달하는 프레임 수 |
| 얇은 벽 너머로 빛이 샘 | 벽 두께와 상관없이 빛 샘 없음 | 빛 샘 테스트 장면(얇은 벽, 동굴, 실내외 경계) |
| 저사양에서 비쌈, 모바일 미지원 | **같은 장면이 모바일부터 고사양까지** 단계별로 동작 | 플랫폼별 고정 시간 예산 안에 들어오는지 |
| 작은 발광체, 식물, 특이한 메시에서 품질 저하 | 메시 종류와 상관없이 안정적 | 문제 사례 모음 장면 |
| 결과를 예측·디버깅하기 어려움 | 원인을 텍스트로 진단 | `bdg gi diagnose` 출력 |

> "버그가 없는 GI"는 어떤 엔진도 약속할 수 없습니다. 대신 **기준 이미지와 자동으로 비교하는 테스트**를 엔진 개발 과정에 넣어, 품질이 나빠지는 변경이 들어오지 못하게 합니다 ([품질 보증](#품질-보증-버그를-줄이는-방법)).

## 구조: 단계별 하이브리드

하나의 기법으로 모든 기기를 덮지 않고, **같은 데이터 위에서 단계를 올려 가는** 구조입니다. 아티스트는 장면을 한 번만 만들고, 기기 성능에 따라 엔진이 단계를 고릅니다.

```
                     ┌──────────────── 공통 데이터 ────────────────┐
                     │ 씬 SDF(거리장) · 머티리얼 · 정적/동적 구분      │
                     └───────┬───────────────┬───────────────┬────┘
   Tier 0  모바일·웹 ─────── 베이크 라이트맵 + 프로브 볼륨 + 반사 프로브
   Tier 1  일반 PC ──────── 동적 프로브 GI (가시성 인식 프로브 격자, SDF 추적)
   Tier 2  고사양 ───────── 래디언스 캐스케이드 + 화면 공간 디테일
   Tier 3  레이 트레이싱 GPU ─ Tier 2 + 하드웨어 레이 트레이싱 반사·그림자 보강
```

| 단계 | 기법 | 대상 | 시간 예산 (목표) |
|---|---|---|---|
| **Tier 0** | 라이트맵 + 구면 조화(SH) 프로브 볼륨 + 반사 프로브. 움직이는 물체는 프로브로 조명 | 모바일, 웹, 저사양 PC | 거의 0 (베이크 데이터 읽기) |
| **Tier 1** | **가시성 인식 프로브 격자**: 프로브마다 주변 거리 정보를 저장해 벽 너머 빛을 차단. 씬 SDF로 광선 추적 (레이 트레이싱 하드웨어 불필요) | 일반 PC, 콘솔급 | 1440p 기준 약 1.5ms |
| **Tier 2** | **래디언스 캐스케이드**: 가까운 곳은 촘촘하게, 먼 곳은 성기게 빛을 계층으로 저장하는 방식. 노이즈가 적어 시간 누적(잔상의 원인)이 거의 필요 없음 + 화면 공간 디테일 | 고사양 PC | 1440p 기준 약 3ms |
| **Tier 3** | Tier 2 + 하드웨어 레이 트레이싱으로 반사와 접촉 그림자 보강 | 레이 트레이싱 지원 GPU | 1440p 기준 약 4.5ms |

시간 예산은 목표치이며, 기준 GPU를 정한 뒤 측정으로 확정합니다.

**품질 단계와의 관계** ([품질 단계](../architecture/rendering-and-platforms.md#품질-단계-5단계-2026-11-21-확정))

| 품질 단계 | GI |
|---|---|
| 감자 | 없음 (조명 연산 없음) |
| 저사양 | 라이트맵만 (저해상도, 움직이는 물체는 주변광 하나) |
| 중사양 | Tier 0 |
| 고사양 | Tier 1 |
| 초고사양 | Tier 2, 레이 트레이싱 GPU면 Tier 3 |

### 루멘과 다르게 설계한 점

1. **베이크 + 동적 차이만 계산 (Delta GI).** 정적인 부분은 미리 베이크하고, 실행 중에는 움직이는 광원·물체가 만든 **차이만** 실시간으로 계산합니다. 전부를 매 프레임 계산하는 방식보다 훨씬 쌉니다.
2. **빛 샘을 구조적으로 막음.** 프로브가 주변 벽까지의 거리를 알고 있어서, 벽 너머의 빛은 계산 단계에서 걸러집니다. 벽 안에 파묻힌 프로브는 자동으로 옮기거나 끕니다.
3. **시간 누적에 덜 의존.** 래디언스 캐스케이드는 처음부터 노이즈가 적어서, 여러 프레임을 섞어 노이즈를 지우는 과정(잔상과 반응 지연의 원인)을 최소화합니다.
4. **메시 표현에 덜 의존.** 메시마다 카드를 만드는 대신 씬 전체의 거리장(SDF)을 써서, 식물이나 특이한 형태에서도 일관되게 동작합니다. 얇은 물체는 SDF 해상도 보정과 화면 공간 정보로 보완합니다.
5. **모든 기기에서 같은 장면.** Tier 0~3이 같은 데이터를 쓰므로, 모바일 빌드를 위해 장면을 따로 만들 필요가 없습니다.

## 아티스트와 AI를 위한 도구

| 도구 | 내용 |
|---|---|
| GI 볼륨 | 영역별 품질·프로브 밀도 조정, 실내·실외 구분 |
| 디버그 뷰 | 프로브 표시(정상/벽 속/꺼짐), 간접광만 보기, 빛 샘 의심 영역 강조, 단계별 비교 분할 화면 |
| 단계 미리보기 | 에디터에서 Tier 0~3을 바로 전환해 모바일 화질 확인 |
| **텍스트 진단** | `bdg gi diagnose forest_01` → 벽 속 프로브 수, 빛 샘 의심 위치, 예산 초과 단계, 고칠 방법을 표로 출력 (AI가 읽고 바로 고칠 수 있음) |
| 베이크 | 백그라운드 점진 베이크, 바뀐 영역만 다시 베이크, 결과는 `.cache/`에 |

```
$ bdg gi diagnose forest_01 --tier 1
probes      12,288 · 정상 11,950 · 벽 속 286 (자동 이동됨) · 꺼짐 52
leaks       2곳 의심 → (14.2, 3.0, -8.5) 벽 두께 0.08m: 두께 0.2m 이상 권장 또는 GI 차단 볼륨 추가
budget      Tier 1  1.42ms / 1.5ms  ✓
```

## 품질 보증 (버그를 줄이는 방법)

1. **기준 경로 추적기 내장.** 오프라인 경로 추적(path tracing)으로 "정답 이미지"를 만드는 기능을 엔진에 넣습니다.
2. **테스트 장면 모음.** 빛 샘(얇은 벽), 동굴, 실내외 경계, 움직이는 광원, 작은 발광체, 식물, 거울 등 알려진 문제 상황을 장면으로 만들어 둡니다.
3. **자동 이미지 비교.** 엔진 코드가 바뀔 때마다 모든 테스트 장면을 단계별로 렌더링하고, 정답 이미지와의 차이를 지각 기반 오차 지표(FLIP 등)로 측정합니다. 기준보다 나빠지면 병합을 막습니다.
4. **성능 회귀 테스트.** 기준 GPU에서 단계별 시간 예산을 넘으면 실패.
5. **반응 시간 테스트.** 광원을 켜고 끄는 장면에서 최종값 도달 프레임 수를 기록해, 반응이 느려지면 실패.

이 테스트 결과는 텍스트 보고서로 남아, 사람과 AI 모두 어떤 변경이 품질을 바꿨는지 추적할 수 있습니다.

## 일정

| 시기 | 내용 |
|---|---|
| **1.0** | Tier 0 (라이트맵 + 프로브 볼륨 + 반사 프로브), 디버그 뷰, `bdg gi diagnose` 기본형 — 반사 프로브·IBL, SH 프로브 볼륨(삼선형, Indirect 보기), 라이트맵(xatlas + CPU 레이 트레이싱, 간접광만)은 2026-11-24 완료(코넬 박스 자동 판정) |
| **L1 이후** (SDL_GPU 렌더러) | 씬 SDF 생성, Tier 1 가시성 인식 프로브 GI, Delta GI |
| **L3** (대형 게임 트랙) | Tier 2 래디언스 캐스케이드, 기준 경로 추적기, 자동 이미지 비교 CI |
| **L3 이후** | Tier 3 하드웨어 레이 트레이싱 보강 |

## 현실적인 한계

- 실시간 GI는 상용 엔진 팀도 수년씩 다듬는 분야입니다. 이 문서의 목표는 방향과 측정 기준이며, 실제 품질은 구현과 측정으로 확인해야 합니다.
- 래디언스 캐스케이드의 3D 적용은 비교적 새로운 기법이라, Tier 2는 연구와 프로토타입 단계를 먼저 거칩니다. 결과가 기대에 못 미치면 Tier 1을 고도화하는 쪽으로 방향을 바꿉니다.
- 언리얼 루멘 역시 계속 개선되고 있어서, 비교는 같은 장면·같은 하드웨어에서 정기적으로 다시 측정합니다.

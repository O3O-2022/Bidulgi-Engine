## 1. 외부 라이브러리

### 고르는 원칙

1. **라이선스:** MIT, BSD, zlib, Apache-2.0, 퍼블릭 도메인만 씁니다. 런타임에는 GPL과 LGPL을 넣지 않습니다. 콘솔 포트와 정적 링크 때문입니다.
2. **감싸서 쓰기:** 외부 라이브러리 타입을 엔진의 공개 API(C API 허브)에 노출하지 않습니다. 각 라이브러리는 엔진 인터페이스 뒤에 두어 나중에 바꿀 수 있게 합니다.
3. **가볍게:** 의존성이 많은 대형 라이브러리(Assimp, Boost, Qt 등)는 피합니다.
4. **고정:** vcpkg 매니페스트에 baseline을 고정합니다. 소스로 들여온 것은 `ThirdParty/`에 버전을 적어 둡니다. 고지문은 `bdg licenses`로 자동 생성합니다.

### 1-1. UI 프레임워크: 자체 구현

정식 에디터와 게임 UI는 Dear ImGui 대신, 언리얼의 Slate처럼 **에디터와 게임 UI가 같은 UI 프레임워크**를 씁니다 (2026-11-21 결정).

| 항목 | 내용 |
|---|---|
| 방식 | 유지형(retained) 위젯 트리. 바뀐 위젯만 다시 배치하고 그림 |
| 레이아웃 | 플렉스(가로·세로 쌓기, 늘이기, 정렬), 겹치기, 앵커, 스크롤, 가상 목록 |
| 그리기 | 엔진 RHI 위의 2D 배칭 렌더러. 둥근 사각형·선·그림자는 SDF 셰이더, 글자는 MSDF |
| 스타일 | 디자인 시스템 토큰을 그대로 읽음. 테마 전환은 토큰 교체만 |
| 입력 | SDL3 이벤트. 포커스, 키보드 이동, 한글 IME 조합을 프레임워크가 처리 |
| 접근성 | 위젯 트리를 그대로 AccessKit 트리로 넘김 (즉시 모드 UI보다 쉬움) |
| 고해상도 | 모든 크기를 배율 단위로 계산, 모니터별 DPI |
| 에디터 전용 부품 | 도킹, 탭, Inspector 자동 생성, 노드 그래프(그래프·애니메이션·머티리얼 공통), 3D 기즈모, 타임라인, 커브·차트 |
| 게임 UI | 같은 위젯을 월드 공간·카메라 공간에 배치 (UMG형 위젯 디자이너) |
| 텍스트 저장 | 에디터 레이아웃과 게임 UI 모두 JSONL로 저장, AI가 수정 가능 |

> **Dear ImGui는 필요한 곳에 써도 됩니다** (MIT). 엔진 개발자용 디버그 창, 실행 중 디버그 오버레이(프로파일러, 물리·GI 디버그 값 조정)처럼 빨리 만들어야 하고 사용자에게 정식으로 보여 주지 않는 곳이 대상입니다. 배포 빌드에서는 빠집니다.

**좋은 점**
- 위젯 하나로 에디터와 게임 UI를 함께 만들고 함께 고칩니다. 에디터에서 만든 부품을 게임에서도 씁니다.
- 디자인 시스템과 화면이 1:1로 맞습니다. ImGui처럼 스타일 한계를 우회할 필요가 없습니다.
- 접근성, IME, 애니메이션(UI 애니메이션 도구), 고해상도를 처음부터 설계에 넣습니다.

**비용과 대응**
- 에디터 개발 초기 속도가 느려집니다. → M0에서는 디자인 시스템 부품 8개(Panel, Tabs, Button, Field, ListRow, Badge, Node, Cover)와 고정 레이아웃만 먼저 만들고, 도킹은 M1로 미룹니다.
- 텍스트 편집(커서, 선택, 실행 취소, IME)은 공수가 큽니다. → 공통 텍스트 입력 위젯 하나만 깊게 만들고 모든 곳에서 재사용합니다.
- 렌더러 개발 전에도 UI를 시험할 수 있게, UI 테스트는 위젯 트리 스냅샷(텍스트)과 이미지 비교로 자동화합니다.

## 2. 디자인

- **기준:** 이미 만든 디자인 시스템(`design-system/project/tokens.json`과 컴포넌트)이 기준입니다.
- **에디터 적용:** UI 프레임워크가 `tokens.json`을 직접 읽습니다(배포 빌드에서는 바이너리로 구움). 색과 간격은 한 곳에서만 바꿉니다.
- **테마:** 어두운 테마(기본), 밝은 테마, 고대비 테마. 모두 같은 토큰에서 만듭니다.
- **글꼴:** UI는 Pretendard, 코드는 JetBrains Mono입니다. 둘 다 OFL 라이선스입니다.
- **아이콘:** Lucide(ISC 라이선스)를 아이콘 폰트로 구워서 씁니다. 엔진 고유 아이콘은 같은 선 굵기로 추가합니다.
- **새 패널 규칙:** 새 UI는 디자인 시스템의 Panel, Tabs, Button, Field, ListRow, Badge, Node 조합으로만 만듭니다. 새 컴포넌트가 필요하면 디자인 시스템에 먼저 추가합니다.
- **게임 UI:** 런타임 위젯은 같은 토큰을 기본 스킨으로 제공하되, 게임마다 바꿀 수 있습니다.

## 3. 패키지 시스템 (엔진 확장과 공유)

Unity의 UPM처럼 쓰고, 텍스트와 git 친화적으로 만듭니다.

### 패키지 하나의 구조

```
com.studio.inventory/
├─ bdgpkg.json        # 매니페스트
├─ Runtime/           # C#, Lua, Graph, 에셋
├─ Editor/            # 에디터 전용 (빌드에서 제외)
├─ Native/            # C++ 모듈 (CMakeLists.txt)
├─ Tests/
└─ AGENTS.md          # AI용 사용법 (선택)
```

```json
{
  "name": "com.studio.inventory",
  "version": "1.2.0",
  "engine": ">=1.0 <2.0",
  "dependencies": { "com.bdg.ui": "^1.0.0" },
  "modules": { "native": "Native", "csharp": ["Runtime", "Editor"] },
  "platforms": ["windows", "android", "web"],
  "permissions": ["editor-script"],
  "license": "MIT"
}
```

### 프로젝트 쪽 파일

| 파일 | 내용 | git |
|---|---|---|
| `Packages/manifest.json` | 원하는 패키지와 버전 범위 | 커밋 |
| `Packages/lock.json` | 실제로 받은 정확한 버전, 출처, 해시 | 커밋 |
| `Packages/<이름>/` | 수정하려고 프로젝트 안에 넣은(embed) 패키지 | 커밋 |
| `~/.bidulgi/cache/packages/` | 받은 패키지 원본. 읽기 전용, 프로젝트끼리 공유 | 제외 |

### 출처

1. **내장:** 엔진에 들어 있는 패키지(물리, UI, 네트워크 등). 엔진 기능도 패키지 단위로 켜고 끕니다.
2. **git:** URL과 태그 또는 커밋. 1.0의 기본 공유 방식입니다.
3. **로컬 경로:** 개발 중인 패키지.
4. **레지스트리 (1.0 이후):** git 저장소에 둔 정적 JSON 색인입니다. 서버 운영 비용이 거의 들지 않습니다.

### 버전 결정

- semver를 쓰고, 패키지마다 한 버전만 허용합니다(UPM 방식). 같은 라이브러리가 두 버전으로 들어오는 문제를 막습니다.
- 충돌이 나면 이유를 텍스트로 보여 줍니다: `bdg pkg why com.bdg.ui`
- `lock.json`이 있으면 항상 같은 결과가 나옵니다. 업데이트는 `bdg pkg update`로만 합니다.

### 언어별 처리

| 내용물 | 처리 |
|---|---|
| C# | 패키지마다 어셈블리 하나(Unity asmdef처럼). 선언한 의존성만 참조할 수 있음 |
| C++ | 엔진 툴체인으로 소스 빌드. 결과는 (엔진 버전, 컴파일러, 플랫폼, 구성) 해시로 캐시. 엔진은 C API로만 연결되므로, 미리 빌드한 바이너리도 엔진 마이너 버전이 바뀌어도 동작 |
| C++ 외부 의존성 | 패키지가 vcpkg 의존성을 선언하면 프로젝트 vcpkg 매니페스트에 합쳐짐 |
| Lua, Graph, 에셋 | 그대로 사용. 에셋 GUID는 패키지 이름 기준으로 고정 |

### 안전

- 설치할 때 권한을 보여 줍니다. 예: 에디터 스크립트 실행, 네트워크, 프로젝트 밖 파일 접근.
- 받은 파일은 `lock.json`의 해시로 확인합니다. 레지스트리 패키지는 서명(minisign 방식)을 확인합니다.
- AI가 패키지를 추가하면 항상 `--dry-run` 결과를 먼저 보여 주고, 사람이 승인해야 설치됩니다.
- 패키지 안의 에셋은 embed하기 전까지 읽기 전용입니다.

### 명령

```
bdg pkg add com.studio.inventory@^1.2   bdg pkg remove <이름>
bdg pkg update [<이름>]                 bdg pkg list / outdated
bdg pkg why <이름>                      bdg pkg embed <이름>
bdg pkg verify                          bdg pkg new / test / publish
```

## 4. 게임 빌드 패키징 (배포 파일 만들기)

```
bdg build --platform android --profile shipping
```

| 단계 | 내용 |
|---|---|
| 1. 수집 | 빌드 목록의 씬에서 참조를 따라가 필요한 에셋만 모음. 쓰이지 않는 에셋은 보고서에 표시 |
| 2. 쿠킹 | 플랫폼별 변환(BC7, ASTC, KTX2, 바이너리 씬). 해시로 캐시해서 바뀐 것만 다시 함 |
| 3. 스크립트 | C# 컴파일, Graph 바이트코드 검증, Lua 바이트코드. 에디터 전용 코드 제거. Python은 기본 제외 |
| 4. 묶기 | `.bpak` 아카이브: zstd 청크 압축과 색인. 기본 게임과 DLC 청크를 나눌 수 있음 |
| 5. 출력 | Windows: 실행 파일 폴더와 zip(Steam 디포 설정 생성). Android: Gradle 템플릿으로 AAB/APK, 서명 키는 사용자가 지정. Web: wasm, html, 에셋 |
| 6. 보고서 | `build-report.txt`: 에셋별 용량, 단계별 시간, 경고. 사람과 AI가 읽고 바로 줄일 수 있음 |

- **패치:** 청크 단위로 비교해 바뀐 청크만 배포합니다.
- **암호화:** `.bpak` 암호화는 선택입니다. 보안이 아니라 쉽게 뽑아 가지 못하게 하는 정도라고 문서에 분명히 적습니다.
- **재현성:** 같은 소스와 같은 `lock.json`이면 같은 결과가 나오게 하고, CI에서 해시로 확인합니다.

### 확인이 필요한 부분

- C# 런타임: Windows는 CoreCLR 또는 NativeAOT, Android는 .NET Android 런타임, Web은 .NET WebAssembly를 후보로 둡니다. 임베드 방식과 용량을 플랫폼마다 프로토타입으로 확인해야 합니다.
- 레지스트리 운영(검수, 악성 패키지 대응)은 1.0 이후에 정합니다.
